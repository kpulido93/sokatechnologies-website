# Change Control

## Objetivo

Evitar que cambios de alcance entren sin evaluacion de impacto, aprobacion y trazabilidad.

## Cuando activar control de cambios

- Nueva funcionalidad fuera de alcance acordado.
- Cambio relevante en integraciones, datos o seguridad.
- Ajuste que afecta calendario, costo o soporte.

## Evaluacion minima

| Punto | Pregunta |
| --- | --- |
| Cambio solicitado | Que se quiere cambiar exactamente. |
| Motivo | Por que surge ahora. |
| Impacto | Que cambia en tiempo, costo, riesgo o complejidad. |
| Dependencias | Que accesos, datos o decisiones hacen falta. |
| Recomendacion | Aceptar, posponer o cotizar aparte. |

## Flujo

1. Registrar solicitud.
2. Validar si realmente esta fuera de alcance.
3. Estimar impacto tecnico y comercial.
4. Presentar opcion recomendada por escrito.
5. Ejecutar solo con aprobacion explicita.
