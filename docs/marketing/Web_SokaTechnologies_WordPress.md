## 8.5 Cómo trabajamos

### Texto

Cada proyecto inicia con una revisión del problema, los usuarios, los datos, los riesgos y el resultado esperado. Así evitamos soluciones improvisadas y definimos un alcance claro.

### Pasos

1. **Diagnóstico**
   Entendemos el proceso actual, los problemas y los objetivos del negocio.

2. **Alcance y propuesta**
   Definimos entregables, tiempos, responsabilidades, exclusiones y criterios de aceptación.

3. **Diseño y desarrollo**
   Construimos una solución simple, mantenible y alineada con la operación real.

4. **Pruebas y despliegue**
   Validamos con usuarios, documentamos y desplegamos con cuidado.

5. **Soporte y mejora continua**

### Cuándo necesitas software a medida

No todo problema requiere desarrollo desde cero. Pero el software a medida puede ser la mejor opción cuando:

- Tu operación tiene reglas específicas.
- Varias personas participan en el mismo proceso.
- Necesitas roles y permisos.
- Debes registrar estados, aprobaciones o historial.
- Usas varias hojas de cálculo para controlar información crítica.
- Necesitas reportes que hoy se preparan manualmente.
- Las herramientas genéricas no se adaptan al flujo real del negocio.
- Necesitas centralizar datos y reducir dependencia de personas específicas.

### Qué podemos construir

- Sistemas administrativos internos.
- Portales de gestión.

# 22. Plugins recomendados

## Principio general

Instalar solo los plugins necesarios. En WordPress, menos plugins bien elegidos suele ser mejor que muchos plugins duplicados.

Antes de instalar cualquier plugin:

- Revisar reputación.
- Revisar fecha de actualización.
- Revisar compatibilidad con la versión actual de WordPress.
- Revisar soporte activo.
- Hacer backup.
- Probar en staging si el cambio es importante.
- No instalar plugins con funciones duplicadas.

## Stack inicial recomendado

| Categoría | Plugin recomendado | Uso | Nota |
|---|---|---|---|
| SEO | Yoast SEO | Titles, meta descriptions, sitemap y SEO básico | Usar un solo plugin SEO |
| Seguridad | Wordfence Security | Firewall, scanner, login security y alertas | Configurar sin exagerar bloqueos |
| Backups | UpdraftPlus | Backups manuales/programados y restauración | Guardar copias fuera del hosting si es posible |
| Cache/rendimiento | LiteSpeed Cache | Cache y optimización si el servidor usa LiteSpeed | Si el hosting no usa LiteSpeed, evaluar alternativa |
| Formularios | Fluent Forms o WPForms Lite | Formularios de contacto y diagnóstico | Elegir uno, no ambos |
| SMTP | WP Mail SMTP | Mejorar entrega de correos de formularios | Configurar con correo corporativo |
| Analítica | Site Kit by Google | Search Console, Analytics y datos básicos | Requiere cuenta Google |
| Cookies/privacidad | Complianz | Banner y gestión de consentimiento de cookies | Útil si se usa analítica |
| Redirecciones | Redirection | 301, 404 y cambios de slugs | Instalar cuando haya necesidad real |
| Diagnóstico técnico | Query Monitor | Debug en desarrollo/staging | No dejar activo en producción si no se necesita |

## Plugins opcionales

| Necesidad | Recomendación |
|---|---|
| Optimización de imágenes | Usar compresión previa antes de subir o un plugin específico si el sitio crece |
| Formularios avanzados | Considerar versión premium solo si hay lógica condicional, multipasos o integraciones |
| Seguridad adicional de login | Usar 2FA si el plugin de seguridad elegido lo permite |
| CRM simple | Empezar con email/hoja de cálculo; integrar CRM cuando haya volumen |
| Newsletter | Agregar solo cuando exista estrategia real de email marketing |
| Multiidioma | No instalar hasta validar si se necesita inglés u otro idioma |

## Recomendaciones para cPanel

Además de plugins, revisar en cPanel:

- SSL activo.
- Versión de PHP soportada y actual.
- Backups del hosting.
- Accesos FTP/SFTP.
- Cuentas de correo.
- Redirecciones.
- Cron jobs si aplica.
- Uso de espacio en disco.
- WP Toolkit si el hosting lo ofrece.
- Logs de errores.

# 23. Plugins que debo evitar

## Evitar por seguridad

- Plugins nulled, pirateados o crackeados.
- Plugins descargados fuera de fuentes confiables.
- Plugins sin actualizaciones recientes.
- Plugins con muchas quejas de seguridad.
- Plugins que piden permisos excesivos.
- Plugins que permiten subir archivos sin controles claros.
- Plugins que ejecutan código o scripts sin revisión.
- Plugins que insertan backlinks, anuncios o tracking no transparente.

## Evitar por rendimiento

- Sliders pesados sin necesidad.
- Builders múltiples al mismo tiempo.
- Plugins de animaciones excesivas.
- Plugins de chat pesados si no hay proceso comercial para responder.
- Plugins de estadísticas que duplican Google Analytics o Site Kit.
- Plugins de optimización duplicados.
- Varios plugins de cache a la vez.
- Plugins de imágenes que procesan demasiado en hosting compartido.

## Evitar por duplicidad

No instalar al mismo tiempo:

- Dos plugins de SEO.
- Dos plugins de cache.
- Dos plugins de seguridad.
- Dos builders visuales.
- Dos plugins principales de formularios.
- Dos plugins de SMTP.
- Dos plugins de cookies.

## Evitar por riesgo comercial o reputacional

- Plugins de envío masivo de WhatsApp sin consentimiento.
- Plugins de scraping.
- Plugins de generación automática de contenido de baja calidad.
- Plugins de apuestas, loterías, captación de jugadores o promoción de juegos.
- Plugins de popups agresivos.
- Plugins que oculten condiciones, rastreen usuarios sin aviso o recolecten datos innecesarios.

# 24. Qué información no debo publicar

## Información de clientes

No publicar:

- Nombres reales de clientes sin autorización.
- Logos sin autorización.
- Dominios, URLs internas o paneles privados.
- Capturas con datos reales.
- Contratos.
- Montos de proyectos.
- Métricas específicas no aprobadas.
- Documentos internos.
- Arquitectura detallada de clientes.
- Flujos sensibles.
- Datos personales.
- Usuarios, correos internos o teléfonos de clientes.
- Credenciales, tokens, claves API o variables de entorno.
- Nombres de bases de datos, servidores o repositorios.

## Información técnica sensible

No publicar:

- IPs de servidores.
- Rutas internas.
- Estructura exacta de infraestructura de clientes.
- Configuraciones de firewall.
- Versiones vulnerables.
- Scripts internos.
- Logs.
- Backups.
- Detalles de seguridad que puedan facilitar ataques.
- Errores de producción.

## Información sobre el cliente de loterías

Para el cliente relacionado con loterías, solo se puede mencionar de forma general y anonimizada:

- Sistemas internos.
- Back-office.
- Reportes.
- Infraestructura.
- Seguridad.
- Auditoría.
- Cumplimiento.
- Administración técnica.
- Automatización operativa interna.

No publicar ni insinuar:

- Mecánicas de apuestas.
- Captación de jugadores.
- Promoción de juegos.
- Participación indebida.
- Evasión de controles.
- Automatizaciones para contactar jugadores.
- Datos de participantes.
- Procesos que reduzcan auditoría, trazabilidad o cumplimiento.

## Información comercial interna

No publicar:

- Márgenes.
- Costos internos.
- Descuentos estratégicos.
- Capacidad operativa real si puede limitar negociación.
- Dependencia de clientes específicos.
- Problemas internos de proyectos.
- Roadmap privado.
- Nombres de proveedores si comprometen seguridad o negociación.

## Información personal

No publicar:

- Datos personales del fundador que no aporten confianza comercial.
- Direcciones personales.
- Documentos de identidad.
- Teléfonos personales si se puede usar canal corporativo.
- Información financiera personal.

# 30. Decisiones recomendadas

1. Construir la web pública principal en WordPress sobre el hosting actual con cPanel.
2. No usar Next.js como web corporativa principal.
3. Usar un tema liviano compatible con Gutenberg.
4. Mantener una cantidad mínima de plugins.
5. Posicionar SokaTechnologies como empresa B2B de soluciones operativas.
6. Priorizar servicios vendibles: software a medida, automatizaciones, sitios web corporativos, infraestructura y soporte.
7. Incluir soporte y mantenimiento como oferta visible desde el inicio.
8. Publicar casos de éxito solo de forma anonimizada.
9. Crear blog desde la primera versión, aunque se publiquen pocos artículos al inicio.
10. Usar formularios simples con privacidad y sin solicitar datos sensibles.
11. Mantener la web como activo comercial vivo, no como folleto estático.
