# Support Process

## Objetivo

Tener un flujo simple para recibir, clasificar y resolver solicitudes de soporte sin improvisacion.

## Canales permitidos

- Canal acordado con el cliente para incidencias.
- Correo o ticket para seguimiento formal.
- Mensajeria directa solo para urgencias y siempre con registro posterior.

## Severidad base

| Severidad | Definicion | Respuesta esperada |
| --- | --- | --- |
| Alta | Sistema caido o proceso critico bloqueado. | Atencion prioritaria y coordinacion inmediata. |
| Media | Falla relevante con workaround parcial. | Revisar en ventana cercana acordada. |
| Baja | Duda, ajuste menor o mejora no bloqueante. | Entrar a backlog o siguiente ciclo. |

## Flujo

1. Recibir solicitud y registrar contexto.
2. Confirmar severidad e impacto.
3. Asignar responsable.
4. Comunicar estado y siguiente hito.
5. Cerrar con causa, solucion y acciones pendientes.

## Metricas minimas

- Tiempo de primera respuesta.
- Tiempo de resolucion.
- Volumen por severidad.
- Incidencias repetidas.
