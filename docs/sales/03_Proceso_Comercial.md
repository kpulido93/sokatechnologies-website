## 1. Objetivo del proceso comercial

El objetivo del proceso comercial de SokaTechnologies es conseguir clientes B2B de forma simple, repetible y profesional, sin depender únicamente de contactos informales o de pocos contratos activos.

El proceso debe ayudar a vender soluciones tecnológicas que resuelvan problemas reales de negocio, especialmente:

- Reducción de trabajo manual.
- Menos errores operativos.
- Mejor trazabilidad.
- Mejor control de procesos.
- Reportes más rápidos y confiables.
- Automatización de tareas repetitivas.
- Integración entre herramientas y sistemas.
- Mejor presencia digital.
- Mayor seguridad, continuidad y soporte tecnológico.

SokaTechnologies no debe vender únicamente programación. Debe vender resultados de negocio mediante software, sitios web, automatizaciones, dashboards, infraestructura y soporte.

### Principios comerciales

- Escuchar antes de proponer.
- Diagnosticar antes de cotizar.
- Vender resultados, no tecnología aislada.
- Priorizar clientes B2B con problemas claros.
- Evitar promesas ambiguas.
- Documentar acuerdos, alcance y próximos pasos.
- Buscar ingresos recurrentes mediante soporte, mantenimiento, hosting, monitoreo o mejoras continuas.
- Proteger margen, tiempo y reputación.

## 2. Perfil de cliente ideal

El cliente ideal de SokaTechnologies es una empresa pequeña o mediana que tiene procesos operativos importantes, pero todavía depende de herramientas manuales, sistemas desconectados o soporte técnico limitado.

### Perfil general

| Criterio | Cliente ideal |
|---|---|
| Tipo de cliente | Empresa B2B, pyme, organización operativa, administradora o proveedor de servicios |
| Ubicación inicial | República Dominicana, Panamá y otros países de Latinoamérica |
| Tamaño | Pequeña o mediana empresa con capacidad de pagar servicios profesionales |
| Decisor | Dueño, gerente general, gerente de operaciones, gerente administrativo, gerente financiero o responsable de tecnología |
| Dolor principal | Procesos manuales, desorden operativo, datos dispersos, reportes lentos o falta de soporte |
| Urgencia | El problema afecta tiempo, dinero, clientes, control interno o toma de decisiones |
| Presupuesto | Tiene capacidad de pagar proyecto inicial y mantenimiento mensual |
| Mentalidad | Valora soluciones prácticas, comunicación clara y soporte continuo |

### Señales positivas

Un prospecto es atractivo cuando:

- Tiene procesos repetitivos que consumen tiempo semanalmente.
- Usa Excel, WhatsApp, correo o documentos compartidos para procesos críticos.
- Tiene varias personas capturando o reenviando la misma información.
- Necesita reportes frecuentes para gerencia.
- Tiene sistemas que no se comunican entre sí.
- Depende de una persona específica para operar o generar reportes.
- Ha tenido errores por captura manual o falta de control.
- Tiene una página web desactualizada o poco profesional.
- No tiene soporte técnico formal, backups o monitoreo.
- Está creciendo y siente que sus procesos actuales ya no escalan.

### Señales negativas

Un prospecto no es ideal cuando:

- Solo busca “lo más barato”.
- No tiene claridad sobre el problema.
- Quiere empezar sin alcance, anticipo ni acuerdos escritos.
- No asigna responsable interno.
- Pide cambios constantes sin aceptar control de alcance.
- Busca soluciones para spam, apuestas, evasión de controles o prácticas riesgosas.
- No respeta tiempos de respuesta, pagos o acuerdos.

## 3. Sectores recomendados

SokaTechnologies debe priorizar sectores donde existan procesos operativos repetitivos, necesidad de control, uso de datos, reportes, soporte tecnológico o presencia digital profesional.

| Sector | Problemas frecuentes | Servicios recomendados |
|---|---|---|
| Administradores de condominios y residenciales | Control de visitantes, portería, reservas, parqueaderos, novedades, trazabilidad | Portik, software interno, dashboards, soporte mensual |
| Empresas de servicios B2B | Seguimiento manual, procesos por correo, reportes dispersos, baja visibilidad | Automatizaciones, CRM simple, dashboards, sistemas internos |
| Logística, transporte y distribución | Control de entregas, reportes manuales, rutas, inventario operativo, comunicación dispersa | Dashboards, integraciones, automatización de reportes, sistemas de seguimiento |
| Firmas contables, legales y consultoras | Gestión de clientes, documentos, vencimientos, tareas repetitivas | Portales internos, automatizaciones, formularios, recordatorios, dashboards |
| Empresas con infraestructura Windows | Inventario manual de equipos, auditoría débil, baja trazabilidad de activos TI | AutoInventario, soporte, infraestructura, documentación técnica |
| Pymes sin equipo técnico interno | Falta de backups, monitoreo, soporte, mantenimiento y seguridad básica | Soporte mensual, cloud/on-prem, backups, monitoreo, mantenimiento |
| Empresas reguladas o auditables | Necesidad de control, reportes, trazabilidad, seguridad y cumplimiento | Sistemas internos, back-office, reportes, auditoría, infraestructura |
| Empresas de cobranzas o gestión operativa | Seguimiento de casos, trazabilidad, reportes, integración de datos | Software interno, dashboards, automatización, soporte con cuidado legal |
| Empresas con web débil o desactualizada | Baja confianza comercial, formularios deficientes, poca claridad de servicios | Sitios web corporativos, landing pages, formularios, mantenimiento web |

### Sectores que no deben priorizarse ahora

- Campañas masivas de WhatsApp o spam.
- Soluciones para captación de jugadores, apuestas o loterías.
- Proyectos que dependan de hardware complejo antes de validar software.
- Inventario comercial genérico si la necesidad real no encaja con AutoInventario.
- Clientes que buscan solo precio bajo sin valorar soporte, seguridad o continuidad.

## 4. Problemas que debo buscar en los prospectos

Durante la prospección y las reuniones, el objetivo es encontrar problemas de negocio que puedan convertirse en proyectos tecnológicos claros.

### Problemas operativos

- Procesos que dependen de Excel.
- Aprobaciones por WhatsApp o correo sin trazabilidad.
- Información duplicada entre archivos o sistemas.
- Reportes preparados manualmente cada semana o cada mes.
- Errores por captura manual.
- Falta de control sobre quién hizo qué y cuándo.
- Dependencia de una sola persona para tareas críticas.
- Procesos que no tienen responsable claro.

### Problemas comerciales

- Sitio web desactualizado o poco confiable.
- Formularios que no llegan al equipo correcto.
- Prospectos que se pierden por falta de seguimiento.
- Falta de datos sobre oportunidades, clientes o ventas.
- Propuestas, cotizaciones o documentos hechos manualmente.

### Problemas de datos y reportes

- Gerencia pide reportes que toman horas o días.
- Datos dispersos en varias hojas o sistemas.
- Indicadores que no se actualizan automáticamente.
- Falta de dashboard para tomar decisiones.
- Diferentes áreas manejan versiones distintas de la información.

### Problemas técnicos

- No existen backups claros.
- No hay monitoreo.
- Servidores o sistemas sin documentación.
- Fallas recurrentes sin causa identificada.
- Credenciales compartidas de forma insegura.
- Dependencias técnicas sin mantenimiento.
- Infraestructura cloud u on-prem mal organizada.

### Problemas de crecimiento

- La empresa creció, pero sigue operando como antes.
- Contratar más personas no resuelve el desorden.
- El negocio necesita escalar sin aumentar errores.
- La gerencia quiere más control sin depender de reportes manuales.

## 6. Proceso paso a paso desde búsqueda hasta cierre

El proceso comercial debe ser simple y repetible.

### Vista general del proceso

| Etapa | Objetivo | Resultado esperado |
|---|---|---|
| 1. Definir segmento | Elegir a quién se va a prospectar | Lista enfocada de empresas |
| 2. Investigar prospectos | Entender empresa, sector y posible dolor | Mensaje personalizado |
| 3. Contactar | Abrir conversación sin presión | Respuesta o conexión |
| 4. Calificar | Confirmar si existe problema, presupuesto y decisión | Prospecto calificado o descartado |
| 5. Diagnosticar | Entender problema, impacto y alcance inicial | Oportunidad clara |
| 6. Recomendar camino | Proponer una siguiente acción razonable | Acuerdo para propuesta o siguiente reunión |
| 7. Enviar propuesta | Documentar alcance, entregables, precio y condiciones | Propuesta formal |
| 8. Seguimiento | Resolver dudas y objeciones | Decisión del cliente |
| 9. Cierre | Acordar inicio, anticipo y próximos pasos | Proyecto ganado |
| 10. Onboarding | Recibir accesos, información y responsables | Inicio ordenado |

### Paso 1: Definir segmento semanal

Elegir un segmento por semana para evitar mensajes genéricos.

Ejemplos:

- Administradores de condominios en Panamá.
- Empresas de servicios en República Dominicana.
- Firmas contables con procesos manuales.
- Pymes con sitio web desactualizado.
- Empresas con infraestructura Windows y necesidad de inventario TI.

### Paso 2: Crear lista de prospectos

Para cada prospecto registrar:

- Empresa.
- País.
- Sector.
- Nombre del contacto.
- Cargo.
- LinkedIn.
- Email.
- WhatsApp si existe relación o fuente permitida.
- Dolor probable.
- Mensaje enviado.
- Estado.
- Próximo seguimiento.

### Paso 3: Contactar con mensaje personalizado

El mensaje debe mencionar el contexto del prospecto y un problema probable, sin sonar invasivo.

Estructura recomendada:

1. Saludo breve.
2. Motivo claro del contacto.
3. Problema de negocio relevante.
4. Resultado que SokaTechnologies ayuda a conseguir.
5. Pregunta simple o invitación a conversar.

### Paso 4: Calificar antes de vender

Antes de preparar propuesta, confirmar:

- Existe un problema real.
- El problema tiene impacto operativo o económico.
- Hay una persona responsable de decidir.
- El prospecto tiene capacidad de inversión.
- El alcance inicial puede definirse.
- El cliente acepta trabajar con acuerdos claros.

### Paso 5: Reunión de diagnóstico

La reunión debe enfocarse en entender el negocio, no en mostrar tecnología de inmediato.

Objetivos de la reunión:

- Entender el proceso actual.
- Identificar fricciones y errores.
- Cuantificar impacto cuando sea posible.
- Confirmar urgencia.
- Identificar decisores.
- Definir si conviene una propuesta.

### Paso 6: Recomendar el siguiente paso

Al final de la reunión, elegir uno de estos caminos:

| Situación | Siguiente paso |
|---|---|
| Dolor claro y cliente calificado | Enviar propuesta |
| Dolor claro pero falta información | Solicitar datos y agendar segunda llamada |
| Cliente interesado pero sin urgencia | Mantener en seguimiento mensual |
| No hay presupuesto o decisión | Nutrir con contenido y revisar más adelante |
| Cliente riesgoso o fuera de enfoque | Rechazar educadamente |

### Paso 7: Enviar propuesta

La propuesta debe enviarse solo cuando exista suficiente claridad sobre problema, alcance, entregables, responsable y decisión.

Toda propuesta debe incluir:

- Problema identificado.
- Objetivo del proyecto.
- Alcance incluido.
- Exclusiones.
- Entregables.
- Cronograma estimado.
- Inversión.
- Forma de pago.
- Responsabilidades del cliente.
- Supuestos.
- Criterios de aceptación.
- Soporte o mantenimiento mensual.
- Condiciones para cambios fuera de alcance.

### Paso 8: Dar seguimiento

El seguimiento debe ser profesional, útil y sin presión excesiva.

Reglas:

- Confirmar recepción de la propuesta.
- Preguntar si hay dudas.
- Resumir valor de negocio.
- Ofrecer ajustar alcance, no bajar precio sin reducir entregables.
- Definir fecha de decisión.

### Paso 9: Cerrar

Un cierre correcto requiere:

- Confirmación escrita.
- Alcance aprobado.
- Forma de pago aceptada.
- Anticipo recibido.
- Responsable del cliente definido.
- Fecha de inicio acordada.
- Canales de comunicación establecidos.

No se debe iniciar trabajo sin anticipo y alcance escrito.

## 7. Criterios para calificar prospectos

Usar estos criterios para decidir si vale la pena invertir tiempo comercial.

### Matriz de calificación

| Criterio | Pregunta | Bueno | Riesgoso |
|---|---|---|---|
| Dolor | ¿Existe un problema claro? | Sí, afecta operación | No sabe qué necesita |
| Impacto | ¿El problema cuesta tiempo, dinero o control? | Impacto evidente | Problema menor o cosmético |
| Urgencia | ¿Quiere resolverlo pronto? | Próximas semanas o meses | “Algún día” |
| Decisor | ¿Está la persona que decide? | Dueño o gerente involucrado | Solo usuario sin influencia |
| Presupuesto | ¿Puede pagar? | Tiene rango o disposición | Busca gratis o muy barato |
| Encaje | ¿SokaTechnologies puede resolverlo bien? | Software, automatización, dashboard, web, soporte o infraestructura | Requiere especialidad fuera del alcance |
| Forma de trabajo | ¿Acepta alcance y anticipo? | Sí | Evita acuerdos claros |
| Riesgo | ¿Hay riesgos legales, éticos o de reputación? | Riesgo bajo o manejable | Riesgo alto |

### Puntaje simple

Asignar 0, 1 o 2 puntos por criterio.

| Puntaje total | Decisión |
|---|---|
| 12 a 16 | Prospecto prioritario |
| 8 a 11 | Prospecto viable, requiere más información |
| 4 a 7 | Bajo potencial, seguimiento ligero |
| 0 a 3 | Descartar |

## 8. Preguntas para reunión de diagnóstico

La reunión debe sentirse como una conversación de negocio. No debe parecer interrogatorio técnico.

### Apertura

- ¿Me puedes contar brevemente cómo opera actualmente esta área o proceso?
- ¿Qué les gustaría mejorar en los próximos meses?
- ¿Qué motivó esta conversación?

### Proceso actual

- ¿Cómo se realiza hoy este proceso paso a paso?
- ¿Quiénes participan?
- ¿Qué herramientas usan actualmente?
- ¿Dónde se captura la información?
- ¿Dónde se consulta o revisa después?
- ¿Qué partes todavía se hacen manualmente?

### Problemas y fricciones

- ¿Qué es lo que más tiempo consume?
- ¿Dónde suelen ocurrir errores?
- ¿Qué tareas se repiten con frecuencia?
- ¿Qué pasa si la persona encargada no está disponible?
- ¿Qué información se pierde o llega tarde?
- ¿Qué parte del proceso genera más estrés o retrabajo?

### Reportes y control

- ¿Qué reportes necesita gerencia?
- ¿Cada cuánto se preparan?
- ¿Cuánto tiempo toma prepararlos?
- ¿Qué decisiones dependen de esos reportes?
- ¿Qué indicador les gustaría ver en tiempo real o con menos esfuerzo?

### Sistemas e integraciones

- ¿Qué sistemas usan actualmente?
- ¿Qué sistemas no se comunican entre sí?
- ¿Dónde se duplica información?
- ¿Hay archivos, correos o formularios que podrían automatizarse?

### Seguridad y continuidad

- ¿Quién tiene acceso a la información?
- ¿Tienen backups definidos?
- ¿Qué pasaría si el sistema o archivo principal falla?
- ¿Tienen documentación técnica o de procesos?

### Impacto de negocio

- Si este problema se resolviera, ¿qué cambiaría para ustedes?
- ¿Cuántas horas por semana creen que se podrían ahorrar?
- ¿Qué errores se reducirían?
- ¿Qué mejoraría para clientes, usuarios internos o gerencia?

### Decisión y presupuesto

- ¿Quiénes deben participar en la decisión?
- ¿Han invertido antes en una solución similar?
- ¿Tienen un presupuesto estimado o prefieren que proponga opciones por fases?
- ¿Cuándo les gustaría tener esto resuelto?
- ¿Cómo evaluarían si el proyecto fue exitoso?

### Cierre de diagnóstico

- ¿Hay algo importante que no hayamos hablado?
- ¿Tiene sentido que prepare una propuesta con alcance y fases?
- ¿Quién debería revisar la propuesta del lado de ustedes?

## 9. Guion de primera llamada

Este guion debe usarse como referencia, no como texto rígido.

### 1. Saludo y contexto

> Hola, {{Nombre}}. Gracias por tomar la llamada. Soy {{Tu Nombre}}, fundador de SokaTechnologies. Ayudamos a empresas a mejorar procesos internos mediante software, automatizaciones, dashboards, sitios web, infraestructura y soporte.

### 2. Alineación de expectativas

> La idea de esta llamada no es venderte algo de inmediato. Quiero entender cómo trabajan hoy, identificar si existe una oportunidad real de mejora y decirte con honestidad si tiene sentido avanzar.

### 3. Permiso para hacer preguntas

> ¿Te parece bien si primero te hago algunas preguntas sobre el proceso actual y luego te comparto posibles caminos?

### 4. Exploración inicial

> Para empezar, ¿qué proceso o área te gustaría mejorar actualmente?

Preguntas de apoyo:

- ¿Cómo lo hacen hoy?
- ¿Qué herramientas usan?
- ¿Qué parte consume más tiempo?
- ¿Dónde se generan errores o retrasos?
- ¿Quién necesita ver la información?
- ¿Qué pasaría si esto se resolviera?

### 5. Resumen del problema

> Para confirmar que entendí: hoy tienen {{problema}}, esto les genera {{impacto}}, y lo que buscan es {{resultado esperado}}. ¿Es correcto?

### 6. Posible recomendación

> Con lo que me cuentas, veo que podría tener sentido empezar con {{diagnóstico / automatización / dashboard / sistema interno / sitio web / soporte}}. Lo ideal sería definir una primera fase pequeña, con entregables claros, para validar valor rápido sin hacer un proyecto demasiado grande desde el inicio.

### 7. Siguiente paso

> El próximo paso sería preparar una propuesta breve con alcance, entregables, tiempo estimado, inversión y opción de soporte. Para hacerla bien, necesitaría confirmar {{dato pendiente}}.

### 8. Cierre

> ¿Quién más debería revisar esta propuesta? ¿Y qué fecha sería razonable para dar seguimiento?

## 12. Cuándo enviar propuesta

No se debe enviar propuesta demasiado temprano. Una propuesta enviada sin diagnóstico suele competir solo por precio.

### Enviar propuesta cuando

- Existe un problema claro.
- El cliente reconoció impacto o urgencia.
- Se identificó un responsable o decisor.
- Se entiende el proceso actual.
- Hay una primera fase razonable.
- El cliente aceptó recibir una propuesta.
- Se conocen restricciones importantes.
- Hay disposición a hablar de inversión.

### No enviar propuesta cuando

- El cliente solo pidió “mándame precio” sin contexto.
- No se entiende el problema.
- No hay decisor involucrado.
- El cliente no responde preguntas básicas.
- El alcance es demasiado ambiguo.
- El prospecto busca comparar precios sin intención real.
- Hay señales de riesgo legal, ético o reputacional.

### Alternativas antes de propuesta

Cuando falta claridad, usar una de estas opciones:

| Situación | Acción recomendada |
|---|---|
| Falta información técnica | Solicitar ejemplos, capturas, archivos o acceso de revisión |
| Falta decisor | Pedir reunión con la persona que aprueba |
| Alcance muy grande | Proponer diagnóstico pagado o fase inicial |
| Dolor poco claro | Hacer segunda llamada de descubrimiento |
| Presupuesto incierto | Presentar rangos orientativos por fases |

### Regla de propuesta

Toda propuesta debe vender una primera fase clara, no un proyecto infinito.

## 13. Cómo manejar objeciones

Las objeciones deben tratarse como señales de duda, no como ataques. El objetivo es entender la preocupación real y responder con calma.

| Objeción | Respuesta recomendada |
|---|---|
| “Está caro” | Entiendo. Podemos revisar el alcance para empezar con una primera fase más pequeña. Prefiero ajustar entregables antes que reducir calidad o dejar cosas críticas por fuera. |
| “No tenemos presupuesto ahora” | Tiene sentido. ¿Este problema es algo que quieren resolver este trimestre o lo dejamos como una mejora futura? También podemos plantear una fase inicial de menor alcance. |
| “Ya tenemos proveedor” | Perfecto. No necesariamente busco reemplazarlo. Podemos apoyar en automatizaciones, dashboards, integraciones o mantenimiento de temas que su proveedor actual no esté priorizando. |
| “Lo hacemos internamente” | Excelente. En ese caso podríamos apoyar como refuerzo externo para tareas puntuales, documentación, pruebas, dashboards o proyectos que el equipo interno no tenga tiempo de ejecutar. |
| “Mándame información” | Claro. Para enviarte algo útil, ¿te interesa más automatización, dashboards, sitio web, infraestructura o soporte? Así te comparto algo más específico. |
| “No es prioridad” | Entiendo. ¿Qué tendría que pasar para que esto se vuelva prioridad? Puedo dejarte algunas recomendaciones y retomarlo más adelante. |
| “Necesito pensarlo” | Claro. ¿Qué punto te gustaría evaluar mejor: inversión, alcance, tiempos, riesgos o prioridad interna? |
| “Otro proveedor lo hace más barato” | Puede ser. Mi enfoque es trabajar con alcance claro, documentación, seguridad básica y soporte posterior. Si quieres, revisamos qué parte del alcance es realmente prioritaria para comparar correctamente. |
| “Queremos todo para ya” | Puedo ayudarte, pero para hacerlo bien conviene priorizar. Propongo separar una primera fase crítica y luego avanzar con mejoras adicionales. |
| “No sabemos exactamente qué necesitamos” | Es normal. En ese caso lo correcto no es cotizar de inmediato, sino hacer un diagnóstico para ordenar problemas, prioridades y posibles soluciones. |

### Regla para descuentos

No ofrecer descuentos sin reducir alcance.

Opciones válidas:

- Reducir funcionalidades.
- Dividir en fases.
- Aplazar integraciones.
- Reducir nivel de soporte.
- Cambiar tiempos de entrega.
- Convertir parte del proyecto en mantenimiento mensual.

## 14. Cuándo rechazar un cliente

Rechazar clientes también protege a SokaTechnologies. No todo ingreso conviene.

### Rechazar o pausar cuando

- El cliente no acepta alcance escrito.
- El cliente no quiere pagar anticipo.
- El cliente cambia constantemente lo que quiere antes de iniciar.
- El cliente presiona para entregar sin información suficiente.
- El cliente quiere acceso a datos, sistemas o prácticas que no son éticas o legales.
- El cliente busca spam, scraping, evasión de controles o automatizaciones abusivas.
- El cliente quiere soluciones relacionadas con apuestas, loterías o captación de jugadores fuera de sistemas internos, back-office, reportes, infraestructura, seguridad, auditoría o cumplimiento.
- El cliente no respeta horarios, acuerdos o canales de comunicación.
- El cliente tiene expectativas imposibles con presupuesto muy bajo.
- El proyecto requiere conocimientos especializados que SokaTechnologies no puede cubrir de forma responsable.
- El riesgo reputacional, legal o técnico supera el beneficio económico.

### Plantilla para rechazar educadamente

> Hola, {{Nombre}}. Gracias por considerar a SokaTechnologies.
>
> Revisando lo que necesitan, creo que en este momento no somos el proveedor adecuado para este proyecto en los términos planteados. Para hacerlo correctamente harían falta condiciones, alcance o validaciones adicionales que hoy no están claras.
>
> Prefiero ser transparente antes que asumir un compromiso que pueda generar riesgos o expectativas incorrectas. Si más adelante el alcance cambia hacia {{tipo de proyecto aceptable}}, con gusto podemos revisarlo.

### Alternativa al rechazo total

Si el cliente es bueno pero el alcance está mal definido:

> Podemos avanzar, pero recomiendo empezar con una fase de diagnóstico o levantamiento. Esa fase nos permitiría definir alcance, riesgos, entregables y presupuesto real antes de construir.

## 16. Rutina semanal de ventas

Como SokaTechnologies es operada por un solo fundador, la rutina comercial debe ser realista y sostenible.

### Objetivo de la rutina

Mantener flujo constante de oportunidades sin descuidar proyectos activos.

### Rutina sugerida

| Día | Actividad principal | Resultado esperado |
|---|---|---|
| Lunes | Definir segmento de la semana y actualizar CRM | Lista priorizada de prospectos |
| Martes | Prospección inicial por LinkedIn y email | Nuevos contactos iniciados |
| Miércoles | Seguimientos y solicitud de referidos | Conversaciones reactivadas |
| Jueves | Reuniones de diagnóstico y preparación de propuestas | Oportunidades calificadas |
| Viernes | Envío de propuestas, revisión de métricas y contenido | Pipeline actualizado |
| Sábado opcional | Crear contenido, casos de éxito o mejoras de portafolio | Activos comerciales |
| Domingo | Descanso o revisión ligera de prioridades | Evitar agotamiento |

### Bloques de tiempo recomendados

| Bloque | Duración | Actividad |
|---|---:|---|
| Prospección | 45 a 60 minutos | Buscar empresas, contactos y enviar mensajes |
| Seguimiento | 30 minutos | Responder, retomar conversaciones, confirmar reuniones |
| CRM | 15 minutos | Actualizar estados y próximas acciones |
| Contenido | 45 minutos | Publicar o preparar material educativo |
| Propuestas | 60 a 90 minutos | Preparar propuestas solo para prospectos calificados |

### Regla semanal mínima

Aunque haya mucho trabajo técnico, no detener ventas.

Mínimo semanal obligatorio:

- 25 prospectos nuevos.
- 30 mensajes enviados.
- 20 seguimientos.
- 5 pedidos de referido.
- 1 publicación educativa.
- Revisión del CRM los viernes.

## Decisiones recomendadas

1. Usar ventas consultivas como proceso principal, no venta agresiva.
2. Priorizar clientes B2B con procesos manuales, reportes dispersos, sistemas desconectados o necesidad de soporte.
3. Vender primeras fases pequeñas con alcance claro, no proyectos enormes desde el inicio.
4. Incluir soporte, mantenimiento o monitoreo mensual en cada propuesta.
5. Rechazar oportunidades que comprometan ética, legalidad, seguridad, margen o reputación.
6. Mantener prospección semanal aunque existan proyectos activos.
