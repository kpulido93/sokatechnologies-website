# Services

## Objetivo

Tener un catalogo base de servicios para orientar ventas, propuesta y delivery sin prometer trabajo ambiguo.

## Catalogo inicial

| Servicio | Cuando aplica | Entregables base | No incluye por defecto |
| --- | --- | --- | --- |
| Discovery y definicion | Cuando el cliente tiene problema pero no solucion cerrada. | Diagnostico, alcance propuesto, backlog inicial. | Implementacion completa. |
| MVP o piloto | Cuando se necesita validar valor rapido. | Solucion acotada, demo operativa, criterios de exito. | Escalado enterprise. |
| Desarrollo a medida | Cuando el flujo de negocio requiere software propio. | Funcionalidades acordadas, despliegue y handoff. | Soporte indefinido sin contrato. |
| Integraciones y automatizacion | Cuando hay tareas manuales entre herramientas. | Flujos automatizados, monitoreo minimo y documentacion. | Licencias de terceros. |
| Mantenimiento y soporte | Cuando el cliente ya opera una solucion. | SLA acordado, seguimiento y mejoras menores. | Nuevos modulos de alto alcance. |

## Checklist de calificacion

- El problema de negocio esta claro.
- Existe sponsor o responsable interno.
- Hay presupuesto, urgencia o dolor real.
- Se puede definir un resultado observable.
- El cliente acepta trabajar con alcance y cambios por escrito.

## Notas comerciales

- Todo servicio debe traducirse a entregables verificables.
- Las exclusiones deben aparecer de forma explicita en propuesta.
- Temas legales, fiscales o regulatorios deben validarse fuera de este repositorio cuando aplique.
