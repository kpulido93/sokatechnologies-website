# Checklist de revision visual

Usar este checklist antes de aprobar cambios visuales en la web WordPress de SokaTechnologies.

## Home

- [ ] La propuesta de valor se entiende en el primer viewport.
- [ ] Hay un CTA principal claro.
- [ ] El hero no depende de texto excesivo.
- [ ] Las secciones principales tienen jerarquia visual consistente.
- [ ] No aparece contenido generico de WordPress como `Sample Page`.
- [ ] No hay claims exagerados ni metricas sin validacion.

## Paginas internas

- [ ] Cada pagina tiene un H1 claro.
- [ ] El encabezado interno explica el objetivo de la pagina.
- [ ] La estructura ayuda a escanear: H2, tarjetas, listas y CTAs.
- [ ] Los textos mantienen tono B2B claro y directo.
- [ ] No hay placeholders visibles salvo que esten marcados como pendientes internos.
- [ ] No hay enlaces rotos o rutas locales visibles.

## Botones

- [ ] El boton principal usa una accion concreta.
- [ ] No hay varios botones primarios compitiendo en la misma seccion.
- [ ] Los botones tienen contraste suficiente.
- [ ] Los estados hover y focus son visibles.
- [ ] El texto cabe sin cortarse en movil.
- [ ] Los enlaces apuntan a paginas aprobadas.

## Tarjetas

- [ ] Todas las tarjetas de una grilla tienen espaciado coherente.
- [ ] Los titulos son especificos y faciles de escanear.
- [ ] El texto no se corta ni se solapa.
- [ ] Las tarjetas funcionan con distinto largo de contenido.
- [ ] No hay iconos o decoraciones inconsistentes.
- [ ] Los casos o ejemplos no revelan clientes reales sin autorizacion.

## Formularios

- [ ] El formulario pide solo campos necesarios.
- [ ] Las labels son visibles.
- [ ] Los campos tienen focus visible.
- [ ] Los mensajes de error son claros.
- [ ] El mensaje de exito se entiende.
- [ ] Hay referencia a privacidad si se recolectan datos personales.
- [ ] No se solicitan datos sensibles.
- [ ] El envio fue probado en entorno aprobado.

## Footer

- [ ] El footer no muestra enlaces genericos del tema padre.
- [ ] La estructura coincide con la navegacion y contenido aprobado.
- [ ] Los datos de contacto son placeholders seguros o datos aprobados.
- [ ] No hay telefonos, emails o WhatsApp no confirmados.
- [ ] Los enlaces legales apuntan a paginas revisadas o pendientes identificadas.
- [ ] El footer es legible en movil.

## 404

- [ ] La pagina 404 mantiene identidad visual de marca.
- [ ] El mensaje es claro y no tecnico.
- [ ] Incluye enlace a Home o navegacion principal.
- [ ] No expone rutas internas, errores, stack traces ni detalles de servidor.
- [ ] El layout funciona en movil.

## CTAs

- [ ] Cada CTA tiene una accion concreta.
- [ ] El CTA final de pagina conecta con Contacto o diagnostico.
- [ ] El texto no promete resultados no validados.
- [ ] El CTA mantiene contraste suficiente.
- [ ] No hay CTAs duplicados que creen ruido.

## Confidencialidad

- [ ] No hay nombres reales de clientes sin autorizacion.
- [ ] No hay logos, capturas, dominios, usuarios o correos internos.
- [ ] No hay datos de cPanel, credenciales, tokens ni llaves.
- [ ] No hay backups, SQL ni exportaciones referenciadas.
- [ ] Los casos de exito estan anonimizados.
- [ ] Los placeholders sensibles siguen siendo genericos y seguros.
